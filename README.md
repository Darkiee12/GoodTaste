# FeastJourney

Mobile-first food discovery for travellers. This repository currently contains a **TanStack Start landing page** and local infrastructure blueprint.

Start with `AGENTS.md`, then `docs/README.md`.

## Run locally

Use Bun 1.4.4 (verified) to install and run tooling:

```sh
bun install --frozen-lockfile
bun run dev
```

Open `http://localhost:3000`. The landing page requires no database, storage service, provider keys, or environment secrets.

```sh
bun run format:check
bun run typecheck
bun run build
bun run start
```

The default production build targets Bun. For Node, rebuild with `bun run build:node` and then run `bun run start:node`. Both outputs use `.output/`, so rebuilding replaces the previous target. Configure the listening address with `HOST` and `PORT`.

The only application route is `/`, with full-document SSR and Start's default server/client entries. `src/routeTree.gen.ts` is generated by Start. No feature routes, catalogue data, server functions, browser storage, or tests are included.

**Languages:** the landing page supports English (`/`) and Vietnamese (`/?lang=vi`). The header language links keep the selection in the URL across reloads and sharing. Unsupported or malformed `lang` values fall back to English. The shared, browser-safe catalogue in `src/shared/i18n.ts` covers page copy, accessibility labels, document language and metadata; TypeScript requires matching keys across languages. There is no automatic browser-language detection or cookie persistence. Zod validates the locale at the root route, and no mutable global locale is used during SSR.

**Architecture direction:** TanStack Start + Effect modular monolith, PostgreSQL, S3-compatible object storage (Garage local-only). Application features will be built later.

**Object storage:** Garage runs as a private, single-node development store. Generate local credentials and follow [object storage setup](docs/infra/object-storage.md). 

**SQL and schema:** Postgres 18 uses a one-shot Flyway container (`infra/compose.yaml`) to apply reviewed `db/migrations/*.sql` before future app startup. Application queries will be domain-local Reylo imports (see `docs/architecture/persistence.md`). The migration folder contains **no application schema yet**.

**Local infrastructure:** copy `infra/.env.example` to `infra/.env`, customize secrets, then run `docker compose --env-file infra/.env -f infra/compose.yaml config --quiet` before starting services. See `docs/infra/operations.md`.

Source references are collected in `docs/references.md`.
